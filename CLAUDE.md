# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

TurboGAP is a Fortran (f90) code for atomistic simulation with machine-learning
interatomic potentials, centered on SOAP-type descriptors (GAP framework). It runs
static predictions (`turbogap predict`), molecular dynamics (`turbogap md`), and
Monte Carlo (`turbogap mc`). This is TurboGAP **2.0**, a from-scratch rewrite of the
original TurboGAP (see `plan.org` for the design rationale) with a modular
`src/<subsystem>/` layout, in contrast to the legacy monolithic version.

The `src/soap_turbo` directory is a **git submodule**
(https://github.com/libAtoms/soap_turbo.git) providing the core SOAP descriptor
routines; it is a separate upstream project vendored in for the build.

## Build

```sh
git clone --recursive http://github.com/mcaroba/turbogap.git   # submodule needed for soap_turbo
make            # builds bin/turbogap and lib/libturbogap.a
make clean      # removes objects/mods/binary, keeps build dirs
make deepclean  # removes build/, bin/, include/, lib/ entirely
```

The top-level `Makefile` `include`s an architecture-specific config from
`makefiles/` (e.g. `Makefile.Ubuntu_gfortran_mpi`, `Makefile.CSC-Mahti_gfortran_openblas_mpi`,
`Makefile.CSC-Puhti_gfortran_mkl_mpi`). Select one by editing this line in the
top-level `Makefile`:

```make
include makefiles/Makefile.Ubuntu_gfortran_mpi
```

Each architecture file sets `F90` (compiler, typically `mpif90`), `PP` (preprocessor
flags, typically `-cpp -D_MPIF90`), `F90_OPTS` (optimization/debug flags), and
`LIBS` (BLAS/LAPACK, e.g. `-lopenblas`). Useful preprocessor debug flags to add to
`F90_OPTS` (see comment at top of `Makefile`): `-D_CHECK_ALLOCATE`,
`-D_CHECK_DEALLOCATE`, `-D_DEBUG`. Other guards used in the source:
`_DEBUG_ALLOC`, `_CHECK_MEMORY`, `_DEBUG_MC`, `_MPIF90`/`_MPIF`, `_OPENMP`, `_GPU`.

The `Makefile`'s `SRC` list defines compile order explicitly (Fortran module
dependency order matters); when adding a new source file it must be inserted into
that list in `Makefile` at the correct dependency position, and the appropriate
pattern rule (`$(BUILD_DIR)/%.o: src/<subdir>/%.f90`) must exist for its
subdirectory — add one if the file lives in a new `src/` subdirectory.

## Tests

```sh
make test                        # builds, then runs the tests_manual/ smoke suite (60s/scenario timeout)
make test TEST_TIMEOUT=300       # override the per-scenario timeout
```

`make test` runs `tests_manual/run_manual_tests.sh`, which discovers every
`tests_manual/*/*/input` (and `tests_manual/*/input`) scenario, maps its category
(`test_mc` → `mc`, `test_md` → `md`, `test_predict` → `predict`) to a `turbogap`
mode, and runs each one in an isolated scratch copy under both `-np 1` and `-np 2`
(override with `TURBOGAP_TEST_NP="1 2 4"`). This is a **smoke test**, not a
numerical-correctness check: there's no golden output to diff against, so "pass"
means no crash signature (`Fortran runtime error`, `Error termination`, `SIGSEGV`,
`forrtl`, non-zero exit) within the timeout. Wired into CI (`.github/workflows/ci.yml`).

Two other test-related trees exist:

- `tests/` — mirrors `src/` per-subsystem, generated by `make_tests.sh` (which
  scaffolds a `test_<file>.f90` module + program per source file with `use`
  statements copied in and a `TODO: test <path>` comment per subroutine). Most of
  these files are still empty stubs; treat them as scaffolding to fill in, not a
  working suite. `src/allocation/test/` is a standalone example with its own
  `Makefile` and a real test suite (`main.f90`, 46 assertions) that builds and
  runs independently: `cd src/allocation/test/tg_memory && make && ./bin/test_tg_memory`.
- `tests_manual/*/*/input` scenario directories also double as manual references —
  run `bin/turbogap <predict|md|mc>` from inside one directly if you need to inspect
  full trajectory/thermo output rather than just pass/fail.

## Architecture

### Module layout

Each `src/<subsystem>/` directory is a self-contained Fortran module group:

- `types/`, `utils/` (`kinds`, `constants`, `error`, `printing`, `functions`,
  `splines`, `calculation`, `timer`, `timing`, `misc`) — foundational types and
  shared helpers used everywhere.
- `control/` — `control_t`/`perform_t` types plus **pure decision functions**
  (`decide_read_xyz`, `decide_md`, `decide_mc`, `decide_write_xyz`,
  `decide_write_thermo`, `check_exit`, …) that decide *what the main loop does
  next* based on state. This is the intended pattern for program flow logic: keep
  it as small pure functions operating on `control_t`/`md_t`/`mc_t`, not scattered
  conditionals in the main loop.
- `md/`, `mc/` — molecular dynamics and Monte Carlo step logic and their own
  `_types.f90` (`md_t`, `mc_t`).
- `gap/` — GAP model evaluation: SOAP-descriptor-based (`calculate_gap_soap.f90`),
  2-body/3-body/core-potential (`gap.f90`), plus `local_properties.f90`.
  Built on top of `soap_turbo/` (the vendored submodule: `soap_turbo_radial`,
  `soap_turbo_angular`, `soap_turbo_compress`, `soap_turbo_functions`,
  `soap_turbo.f90`).
- `vdw/` — van der Waals corrections.
  `madlib/` (+ `exp_types.f90`) — experimental-observable fitting (XRD/XPS/PDF/ND).
- `neighbors/` — neighbor list construction.
- `xyz/` — extended-XYZ reading/writing.
- `read/` (+ per-subsystem `read_*.f90`, e.g. `read_control.f90`, `read_md.f90`,
  `read_mc.f90`, `read_gap.f90`, `read_vdw.f90`, `read_exp.f90`) — input file
  parsing, one reader module per subsystem's option block, coordinated via
  `read_files.f90`.
- `mpi/` — MPI collective helpers (`mpi_utils.f90`) used for parallel
  gather/broadcast of calculation results, guarded by `_MPIF90`.
- `allocation/` — a WIP centralized allocation-tracking layer (`tg_memory`,
  `tg_alloc`): wraps `allocate`/`deallocate` for int/dp/logical arrays of rank 1–5
  to track running/peak memory (`memory_total`, `memory_max`) per rank, reporting
  via `_CHECK_ALLOCATE`/`_DEBUG_ALLOC`. `tg_memory.f90` is *generated* from
  `tg_memory.fpp` via the `fypp` Fortran preprocessor/templating tool (loops over
  precisions `int`/`dp`/`logical` × ranks 1–5) — **edit the `.fpp` template and
  regenerate, don't hand-edit `tg_memory.f90` directly**. Per the commit history
  ("added allocation now make it pervasive"), this tracked-allocation pattern is
  being rolled out across the whole codebase — prefer `tg_allocate`/`tg_deallocate`
  over bare `allocate`/`deallocate` in code you touch here.
- `third_party/` — vendored external code under its own license
  (`bussi_thermostat`, `vc-sqnm` — variable-cell stable quasi-Newton optimizer),
  kept licensing-independent from the rest of the tree.

### Program entry / control flow

`src/turbogap.f90` is a two-line entry point calling `turbogap_main::turbogap_run`.
`src/turbogap_main.f90` (`turbogap_run`, ~1000 lines) declares essentially all
top-level state (control flags, `md_t`/`mc_t`, `state_t`, species info, per-model
`calculation_t` energy/force/virial containers, GAP hyperparameter arrays, MPI
rank/split info) and runs `main_loop: do while (.not. exit_loop)`, delegating
per-step decisions to the pure functions in `control_interface` and per-physics
work to the subsystem modules (`md_interface`, `mc_interface`, `calculate_gap_soap`,
`gap`, `vdw_interface`, neighbor list building, etc.), with MPI
broadcast/collection interleaved when built with `_MPIF90`.

### Licensing header convention

Every `.f90` source file carries a standardized "HND" copyright banner block at
the top (ASL license, TurboGAP + Miguel A. Caro + contributor names). New source
files should carry the same header — see `copyright_text` for the canonical text,
or use `create_copyright.sh` (backs up files, then prepends the header, per-file
substituting the filename) to apply it in bulk.

## Formatting & pre-commit

`.editorconfig` sets indent (3 spaces for `.f90`/`.fpp`/`.for`/etc., tabs for
Makefiles) and line-ending conventions. `fprettify` (config: `.fprettify.rc`) is
the Fortran auto-formatter; its scope is the explicit whitelist in
`.fprettify-files.txt` (one path per line — the real, compiled source files, i.e.
what `$(SRC)` in the `Makefile` maps to), **not** a blanket `find src -name
'*.f90'`: that would also catch the `soap_turbo` submodule, vendored
`third_party/` code, generated `src/allocation/tg_memory.f90` (regenerate from
`tg_memory_dims.fpp` via `fypp`, never hand-edit), and dead prototype files under
`src/allocation/` and `src/gpu/`. When adding a new real source file, add it to
both `Makefile`'s `SRC` list and `.fprettify-files.txt`.

```sh
make format          # fprettify -c .fprettify.rc, in place, over .fprettify-files.txt
make format-check     # same, but diff-only; this is what CI runs and fails the build on drift
```

Optional local pre-commit hooks (`.pre-commit-config.yaml`) catch the same
formatting drift — plus a missing TurboGAP copyright header, or an accidentally
staged `.mod`/`.o`/`.a` build artifact — before push instead of after:

```sh
pip install pre-commit fprettify
pre-commit install          # once per clone
pre-commit run --all-files  # on demand
```

## Notes for future refactoring

`plan.org` documents the intended 2.0 architecture in detail (typed
`control_t`/`calculation_t`/parameterized-derived-type ideas, FORD for
documentation) and is a useful reference before making structural changes to
control flow or core types — check it for prior art/rationale before
re-deriving a design. Ford (Fortran documentation generator) is referenced there
as the intended docs tool but isn't currently wired into the build.
